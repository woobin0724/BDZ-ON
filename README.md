# 온잇다 — 기후·에너지 취약 고령층 케어 플랫폼

> 한전KDN 빛가람 AI·ICT 경진대회 출품용 **시연 프로토타입(MVP)**

기상 특보와 가구별 전력 사용 패턴(가상 AMI 데이터)을 함께 분석해 홀로 계신 어르신의 위험도를 **안전 / 주의 / 위험** 3단계로 판정합니다. 판정 결과는 네 가지 서비스에 쓰입니다.

| 카테고리 | 하는 일 |
|---|---|
| ① 기후 안전 | 폭염인데 냉방 전력을 쓰지 않거나, 한파인데 난방 전력을 쓰지 않으면 위험 알림 |
| ② 안부 돌봄 | 생활 전력 변화가 없으면 1차 푸시 → 미응답 시 2차 음성 알림 → 계속 미응답 시 복지사 대시보드 적색 경보 |
| ③ 에너지 복지 | 위험도가 높은데 전기를 적게 쓰는 가구에 에너지 지원 제도 안내 |
| ④ 계절 식단 | 날씨·계절에 맞는 제철·보양 식재료 추천, 값이 비싸면 대체 식재료 제안 |

> ⚠️ **모든 개인정보는 가짜입니다.** 화면에 나오는 어르신 10명의 이름·나이·주소·연락처·보호자·담당 복지사, 그리고 전력 사용량은 전부 시연용으로 만든 가상 데이터이며 실제 인물·가구와 관계가 없습니다. 주소는 "○○동 (가상 주소)" 형태이고 좌표는 전북 지역의 임의 지점입니다.

## 1. 빠른 시작 (윈도우)

**준비물**: [Node.js 20 이상 (LTS)](https://nodejs.org), [Python 3.10 이상](https://www.python.org/downloads/) — Python 설치 시 *Add python.exe to PATH* 를 체크하세요.

1. 이 폴더에서 **`start.bat` 을 더블클릭**합니다.
2. 처음 실행할 때만 패키지를 설치합니다 (인터넷 필요, 1~3분).
3. 준비가 끝나면 브라우저에 **시연 컨트롤 패널**(http://localhost:8000/demo)이 자동으로 열립니다.
4. 끝낼 때는 검은 창을 닫으면 됩니다.

> 설치를 한 번 마친 뒤에는 **인터넷 없이 100% 동작**합니다. (`.env` 에 API 키가 없으면 mock 모드가 기본값)

맥·리눅스는 `./start.sh` 를 실행합니다.

### 명령어로 실행하기

```bash
npm run setup   # 최초 1회: 파이썬 가상환경 + 백엔드/프론트엔드 패키지 설치, .env 생성
npm run dev     # 개발 모드: 백엔드(8000) + 프론트 개발 서버(5173)를 한 번에 실행 → http://localhost:5173
npm run demo    # 시연 모드: 화면을 빌드해 백엔드 한 곳(8000)에서 함께 제공 → http://localhost:8000
npm test        # 위험도 엔진 단위 테스트
```

심사장에서는 `start.bat`(= `npm run demo`)을 권장합니다. 포트가 하나라 설정이 단순하고, 개발 서버보다 가볍습니다.

### 화면 주소

`npm run demo` 기준입니다. `npm run dev` 로 실행했다면 포트만 `5173` 으로 바꾸세요.

| 화면 | 주소 | 용도 |
|---|---|---|
| 처음 화면 | http://localhost:8000/ | 세 화면으로 가는 입구 |
| **A. 어르신 앱** | http://localhost:8000/app?id=1 | 모바일 화면 (PC에서는 휴대폰 틀 안에 표시, `&frame=0` 이면 틀 없이) |
| **B. 복지사 대시보드** | http://localhost:8000/dashboard | 지도·위험 가구 목록·차트·알림 로그 |
| **C. 시연 컨트롤 패널** | http://localhost:8000/demo | 기상 상태·가구 시나리오 전환 |
| ★ 분할 시연 화면 | http://localhost:8000/split?id=1 | 조작 막대 + 어르신 앱 + 대시보드를 한 화면에 (1920×1080 권장) |
| API 문서 | http://localhost:8000/docs | Swagger UI (모든 API 를 직접 눌러볼 수 있음) |

같은 와이파이의 휴대폰에서 어르신 앱을 열려면 `npm run dev` 로 실행하고 `http://<PC의 IP>:5173/app?id=1&frame=0` 으로 접속하세요. 윈도우 방화벽 허용이 필요할 수 있습니다.

## 2. 시연 순서 (예시)

시연 컨트롤 패널 또는 분할 시연 화면에서 진행합니다. 시연 모드가 켜져 있으면 알림 단계가 **10초 간격**으로 진행됩니다.

1. **초기화**: `전 가구 정상으로 초기화` → 지도의 마커가 모두 초록색이 됩니다.
2. **폭염**: 기상 `폭염` → 정상 가구는 냉방 사용이 늘어 계속 '안전'입니다. 판단 근거에 "평소의 350%로 늘어 냉방을 사용하고 있습니다"가 표시됩니다.
3. **냉방 미사용**: 1번 김순자 어르신 시나리오를 `냉·난방 미사용` 으로 바꿉니다.
   - 대시보드: 빨간 마커, 판단 근거 "폭염 특보 중이지만 오후 냉방 시간대 전력 사용이 평소의 101% 수준으로, 냉방 사용 기록이 없습니다", 에너지 복지 안내 대상 표시
   - 어르신 앱: 1차 알림 화면과 '괜찮아요' 버튼. 응답하면 에너지 지원 카드도 볼 수 있습니다.
4. **미응답**: 10초 뒤 2차 음성 알림이 나오고 앱이 안내 문구를 읽어줍니다. 10초가 더 지나면 대시보드에 **적색 경보** 배너가 뜹니다.
5. **응답**: 앱의 `괜찮아요` 또는 대시보드의 `확인 처리` → 알림 로그에 응답 여부와 시각이 남습니다.
6. **무변화**: 다른 가구를 `무변화` 로 바꾸면 "최근 18시간 동안 생활 전력 변화가 거의 없습니다"로 '주의'가 됩니다. 80세 이상 독거 어르신이면 한 단계 높여 '위험'입니다.

> **음성 안내**: 브라우저는 사용자가 화면을 한 번 눌러야 소리를 낼 수 있습니다. 어르신 앱은 처음에 `화면을 눌러 시작하기` 를 한 번 눌러 주세요.
> 윈도우에서는 기본으로 설치된 한국어 음성(Microsoft Heami)을 사용하므로 오프라인에서도 읽어줍니다. 음성이 나오지 않으면 *설정 → 시간 및 언어 → 음성* 에서 한국어 음성을 설치하세요.

## 3. 기능 설명

### 핵심 엔진: 위험도 분석 (규칙 기반, AI 모델 학습 없음)

입력은 기상 상태(평상/폭염/한파), 가구의 1시간 단위 전력 사용량 7일치, 나이, 독거 여부입니다.

| 규칙 | 조건 (기본값) | 결과 |
|---|---|---|
| 폭염 냉방 미사용 | 폭염 특보 기간(최근 3일) 13~21시 평균 사용량이 특보 전 같은 시간대의 **1.3배 미만** | 위험 |
| 한파 난방 미사용 | 한파 특보 기간 19~06시 평균 사용량이 특보 전의 **1.3배 미만** | 위험 |
| 생활 전력 무변화 | 현재부터 거꾸로 **12시간 이상** 시간당 사용량의 (최대-최소)가 **0.06 kWh 이하** | 주의 |
| 고령·독거 가중 | **80세 이상 + 독거**이고 다른 위험 신호가 있으면 한 단계 높임 (주의 → 위험) | +1단계 |

- 결과에는 **판단 근거 문장**(복지사용)과 **쉬운 안내 문장**(어르신용)이 함께 담깁니다.
- 점수(0~99)는 같은 단계 안에서 정렬하는 데 씁니다.
- **규칙·임계값·문구·알림 대기 시간은 전부 [`backend/app/risk_rules.yaml`](backend/app/risk_rules.yaml) 한 파일**에 있습니다. 저장하면 서버를 다시 켜지 않아도 다음 재계산부터 반영됩니다.
  - 예: 특보 중에는 신호가 없어도 80세 이상 독거 어르신을 '주의'로 올리려면 `apply_when_safe_during_alert: true`

### 가상 전력 데이터 생성기

[`backend/app/seed/power_generator.py`](backend/app/seed/power_generator.py) — 가구별 1시간 단위 사용량(kWh) 최근 7일치(168개)를 만듭니다. 같은 가구·같은 시각에는 항상 같은 값이 나옵니다.

| 시나리오 | 패턴 |
|---|---|
| 정상 | 상시 부하(냉장고 등) + 아침·점심·저녁 생활 패턴. 기온 30℃ 이상이면 냉방, 0℃ 이하면 난방 사용 증가 |
| 냉·난방 미사용 | 생활 패턴은 있지만 특보 중에도 냉·난방이 늘지 않음. 평소에도 아껴 쓰는 저사용 가구 (에너지 빈곤 의심) |
| 생활 전력 무변화 | 최근 18시간 동안 상시 부하만 거의 일정하게 남음 (안부 이상 의심) |

기온도 같은 방식으로 만듭니다. 폭염·한파 상태에서는 최근 3일이 특보 기간, 그 전 4일이 평소입니다. 대시보드 차트에 특보 기간이 음영으로 표시됩니다.

### 안부 알림 흐름

```
위험도 상승(안전→주의, 주의→위험)
   └─▶ 1차 푸시: 어르신 앱 알림 화면 + [괜찮아요]
          └─(미응답 30분 / 시연 모드 10초)─▶ 2차 음성: 앱이 안내 문구를 자동으로 읽어줌
                 └─(미응답 30분 / 시연 모드 10초)─▶ 적색 경보: 대시보드 빨간 배너 + 보호자 연락처
[괜찮아요] 응답 · 복지사 [확인 처리] · 위험 신호 해소 → 종료, 모든 단계는 알림 로그에 기록
```

- 단계 진행 타이머는 **백엔드**에서 돌아갑니다. 어르신 앱 화면이 꺼져 있어도 적색 경보가 올라갑니다.
- 시연 모드는 패널에서 켜고 끌 수 있습니다. 처음 상태는 `.env` 의 `DEMO_MODE` 로 정합니다.

### 에너지 복지 안내

위험도가 '주의' 이상이면서 **저사용 가구**(최근 3일 하루 평균 4.5 kWh 이하)이거나 **냉·난방 미사용**으로 판정된 가구에 안내 카드를 보여줍니다.

> 📝 안내 문구는 **placeholder** 입니다. [`backend/app/data/welfare.json`](backend/app/data/welfare.json) 의 `detail` 에 `TODO: 공식 정보 확인 후 수정` 이라고 표시해 두었습니다. 지원 대상·금액·기간은 공식 공고를 확인한 뒤 채워 주세요.

### 계절 식단

[`backend/app/data/diet.json`](backend/app/data/diet.json) — 봄·여름·가을·겨울 식단과, 특보 때 계절보다 우선하는 폭염·한파 보양 식단이 있습니다. 식재료 가격이 평년보다 **20% 이상** 비싸면 대체 식재료와 그 가격을 보여줍니다.

### 화면

- **어르신 앱**: 글씨 24px 이상, 한 화면에 카드 하나(이전/다음 큰 버튼), 모든 카드에 `음성으로 듣기`. 안부 확인이 진행 중이면 카드 대신 전체 화면 알림이 뜹니다.
- **복지사 대시보드**: 위험도 색상 마커 지도(초록/노랑/빨강, 적색 경보는 진한 테두리), 위험도 순 목록과 판단 근거, 선택 가구의 7일 전력·기온 차트(표로 보기 지원), 알림 로그.
  - 전력과 기온은 단위가 달라 한 그래프에 두 개의 세로축으로 겹치면 잘못 읽기 쉽습니다. 그래서 **같은 시간축을 공유하는 두 그래프를 위아래로 붙였습니다.** 마우스를 올리면 두 그래프에 같은 시각이 함께 표시됩니다.
- **시연 컨트롤 패널**: 기상 상태 전환, 가구별 시나리오 전환, 시연 모드, 초기화, 안부 확인 수동 시작·다음 단계·대신 응답·복지사 확인.

모든 화면은 서버 상태가 바뀌면 **즉시(SSE) 갱신**됩니다. 연결이 끊겨도 10초마다 다시 불러옵니다.

## 4. mock ↔ 실제 API 전환

루트의 `.env` 파일(`npm run setup` 이 `.env.example` 을 복사해 만듦)에 키를 넣고 서버를 다시 켜면 됩니다.

```ini
# 기상청 (공공데이터포털 → '기상청_단기예보 조회서비스', '기상청_기상특보 조회서비스' 활용 신청, 일반 인증키(Decoding))
KMA_API_KEY=발급받은키

# KAMIS 농산물 가격정보 (www.kamis.or.kr → Open API 신청)
KAMIS_CERT_KEY=발급받은키
KAMIS_CERT_ID=발급받은ID
```

| 항목 | 키 없음 (기본) | 키 있음 |
|---|---|---|
| 기상 | `data/weather_mock.json` 프로필 | 전북 지역 폭염·한파 특보 여부(특보 현황) + 전주 단기예보(현재·최고·최저 기온, 하늘) |
| 농산물 가격 | `data/prices_mock.json` | KAMIS 최근일 소매가격. 평년은 1개월 전·1년 전 가격의 평균 |

- 키가 있어도 **호출이 실패하면 자동으로 mock 으로 대체**합니다. 심사장 네트워크 장애에 대비한 동작입니다.
- 기상 키가 있으면 시연 패널에 `📡 실제 기상청` 버튼이 생깁니다. `평상/폭염/한파` 버튼을 누르면 실제 API 보다 그 값이 우선합니다.
- 실제 API 를 쓰더라도 가구 전력 데이터는 가상 데이터입니다. 실제 AMI 연동은 이 MVP 범위 밖입니다.
- 실제 API 연동 코드는 키 없이 작성했기 때문에 실제 응답으로는 아직 검증하지 못했습니다. 키를 발급받으면 `/docs` 에서 `/api/meta`, `/api/app/1/home` 의 `source` 값으로 동작을 확인하세요.

## 5. 오프라인 동작

| 요소 | 오프라인 처리 |

## 8. 주요 API

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/meta` | 서비스 정보, 현재 기상 상태, 시연 모드, API 사용 여부 |
| GET | `/api/elders` | 전체 가구 (위험도 순, 판단 근거·진행 중 안부 확인 포함) |
| GET | `/api/elders/{id}/timeseries` | 최근 7일 1시간 단위 전력 + 기온 |
| GET | `/api/dashboard/summary` | 단계별 가구 수, 적색 경보 수 |
| GET | `/api/alerts` | 알림 로그 (`elder_id` 로 거르기 가능) |
| POST | `/api/checkins/{id}/ack` | 복지사 확인 처리 |
| GET | `/api/app/{id}/home` | 어르신 앱 화면 데이터 (날씨·위험·안부 확인·복지·식단) |
| POST | `/api/app/{id}/respond` | '괜찮아요' 응답 |
| POST | `/api/demo/weather` | `{"mode": "normal" \| "heatwave" \| "coldwave" \| "auto"}` |
| POST | `/api/demo/scenario` | `{"elder_id": 1, "scenario": "normal" \| "no_hvac" \| "flat"}` |
| POST | `/api/demo/demo-mode` | `{"enabled": true}` |
| POST | `/api/demo/reset` | `{"preset": "mixed" \| "all_normal"}` |
| GET | `/api/events` | 실시간 갱신 이벤트 (SSE) |

## 9. 참고 및 한계

- 이 프로젝트는 **공모전 시연용 프로토타입**입니다. 인증·권한, 개인정보 암호화, 실제 푸시 발송(FCM 등), 실제 AMI 연동은 포함하지 않았습니다.
- 위험도는 규칙 기반 판정이며 의료적 판단이 아닙니다. 식단 정보도 일반적인 안내 수준입니다.
- 지도 경계 데이터: [southkorea/southkorea-maps](https://github.com/southkorea/southkorea-maps) (통계청 2013년 행정구역 경계, 간소화). 온라인 지도: © OpenStreetMap contributors.
- 데이터베이스(`backend/onitda.db`)는 처음 실행할 때 자동으로 만들어집니다. 처음 상태로 되돌리려면 패널의 초기화 버튼을 누르거나, 서버를 끈 뒤 이 파일을 지우세요.
